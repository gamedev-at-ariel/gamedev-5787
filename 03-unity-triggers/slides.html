פעולות קלט על מסך מגע

בסצינה movement-and-control החללית זזה עם החיצים (InputMover + פעולת הקלט Move).
בטלפון אין מקלדת.

הפתרון: ג'ויסטיק על המסך - בלי לשנות אף שורת קוד.

הרעיון: גיימפד וירטואלי

  • OnScreenStick "מתחזה" לגיימפד: גרירה של התמונה מזינה את <Gamepad>/leftStick.
  • InputMover עדיין קורא move.ReadValue<Vector2>() - לא יודע ולא אכפת לו מאיפה הגיע הערך.
  • זה היתרון של פעולת קלט: הקוד מדבר על "תזוזה", לא על "חיצים".

שלב 1: הקלט

  1. בפעולה Move של InputMover מוסיפים binding: <Gamepad>/leftStick.
    החיצים נשארים - כדי לבדוק גם במחשב.
  2. מוסיפים EventSystem עם InputSystemUIInputModule.
    בלעדיו אף רכיב ממשק לא מקבל מגע.

למה זה לא עובד?

סימפטוםמה לבדוק
הג'ויסטיק לא מגיב בכלל. יש EventSystem בסצינה? יש לידית Raycast Target?
הידית זזה, החללית לא. ה-Control Path תואם ל-binding של Move?
הג'ויסטיק קטן מדי או גדול מדי בטלפון. Canvas Scaler על Scale With Screen Size?
הג'ויסטיק מתחת לפינה המעוגלת או לפס המחוות. Player Settings - Resolution and Presentation - Render outside safe area - False.

ומה עם ירי?

אותה שיטה בדיוק, עם כפתור:

  • OnScreenButton עם Control Path <Gamepad>/buttonSouth.
  • בפעולה Fire - binding תואם: <Gamepad>/buttonSouth.
  • ממקמים בפינה הימנית התחתונה - לאגודל הימני.

תרגיל: הוסיפו כפתור ירי לסצינת הלייזר.

דגמים - Prefabs

Prefab = pre-fabricated = דגם מוכן מראש של עצם-משחק, המאפשר לייצר עותקים רבים של אותו עצם.

  1. יצירת דגם ע"י גרירה מההיררכיה
  2. יצירת עותק ע"י גרירה לסצינה
  3. Override - החלפת מאפיין של דגם באחד העותקים
  4. שינוי מאפיין בדגם משנה את כל העותקים שלא הוחלפו
  5. Apply - העתקת מאפיין מעותק אחד אל הדגם

התנגשויות

"התנגשות" ביוניטי = חפיפה מרחבית בין עצמים.

הרכיבים הדרושים:

  1. לשני העצמים המתנגשים חייב להיות רכיב Collider - המגדיר את הנפח שהם תופסים במרחב.
  2. לפחות לאחד משני העצמים המתנגשים חייב להיות רכיב RigidBody - המגדיר את התנועה של העצם במרחב.

מעבר לסצינה אחרת

SceneManager.LoadScene:

  1. לפי שם או מספר סידורי;
  2. שניהם "מסוכנים".
  3. בשני המקרים יש להוסיף סצינות ל Build Settings.

העברת משתנים בין סצינות:

  1. משתנה סטטי - קל בהתחלה, קשה בהמשך.
  2. דגם עיצוב סינגלטון - להיפך.

מחזור החיים של עצם

יוניטי קוראת לפונקציות של הרכיבים שלכם בסדר קבוע:

גם כשמכבים רכיב enabled = false או עצם SetActive(false) נקרא OnDisable, וכשמדליקים שוב - OnEnable.

מה עושים בכל פונקציה?

פונקציה מתי נקראת? מה עושים בה?
Awake פעם אחת, כשהעצם נוצר. מאתחלים את העצם עצמו: GetComponent.
OnEnable אחרי Awake, ובכל פעם שהרכיב מופעל. נרשמים לאירועים, מפעילים פעולות קלט.
Start פעם אחת, לפני ה-Update הראשון. פונים לעצמים אחרים.
Update בכל פריים. קלט, תנועה, לוגיקה.
LateUpdate בכל פריים, אחרי כל ה-Update. מצלמה שעוקבת אחרי השחקן.
OnDisable כשהרכיב מכובה או נמחק. מבטלים הרשמות, מכבים פעולות קלט.
OnDestroy כשהעצם נמחק. משחררים משאבים.

כלל 1: Awake ו-Start

Awake - רק לעצמך. Start - גם לאחרים.


public class ScoreDisplay : MonoBehaviour {
    Text label;
    void Awake() {      // only this object
        label = GetComponent<Text>();
    }
    void Start() {      // now it is safe to use others
        ScoreManager.Instance.ScoreChanged += Show;
    }
}

למה? "הסדר בין עצמים שונים אינו קבוע" (תיעוד יוניטי).
אם ה-Awake של ScoreDisplay ירוץ לפני ה-Awake של ScoreManager - Instance עוד יהיה null.

כלל 2: מראה


void OnEnable() {
    fire.Enable();
    fire.performed += Shoot;
}

void OnDisable() {
    fire.performed -= Shoot;
    fire.Disable();
}
  • כל מה שעושים ב-OnEnable - מבטלים ב-OnDisable, בסדר הפוך.
  • OnDisable נקרא תמיד לפני שהעצם נעלם: כיבוי, Destroy, מעבר סצינה.
  • שכחתם? החללית שהושמדה תמשיך "לירות" - ותזרוק שגיאות.

Instantiate - מתי מה רץ?


Laser laser = Instantiate(laserPrefab, pos, rot);
// Awake and OnEnable of the laser have ALREADY run here
laser.speed = 10;
// Start has NOT run yet - it will see speed = 10
  • Awake ו-OnEnable רצים מיד, בתוך Instantiate.
  • Start רץ רק לפני ה-Update הראשון של העצם החדש.
  • ולכן: ערכים שנקבעים אחרי Instantiate - קוראים אותם ב-Start, לא ב-Awake.

Destroy - לא מיד!

Destroy מסמן את העצם למחיקה בסוף הפריים. הקוד שאחריו ממשיך לרוץ.

באג נפוץ: שני לייזרים פוגעים באותו אויב באותו פריים ← שני טריגרים ← ניקוד כפול. 


bool isDead;

void OnTriggerEnter2D(Collider2D other) {
    if (isDead) return;             // already hit
    if (!other.CompareTag("Laser")) return;
    isDead = true;
    ScoreManager.Instance.Add(10);
    Destroy(gameObject);            // at the end of the frame
}

מה קורה במעבר סצינה?

  • כל העצמים בסצינה הישנה: OnDisable → OnDestroy.
  • כל העצמים בסצינה החדשה: Awake → OnEnable → Start.
  • מה שורד: משתנים סטטיים, ועצמים עם DontDestroyOnLoad.

ולכן "משתנה סטטי - קל בהתחלה, קשה בהמשך":

  • מונה סטטי לא מתאפס כשמתחילים שלב מחדש.
  • מי שנרשם לאירוע סטטי ולא ביטל ב-OnDisable - נשאר רשום גם אחרי שנמחק.

פריים אחד

  1. קריאת קלט מהמקלדת, העכבר, המסך.
  2. Update של כל הרכיבים.
  3. LateUpdate של כל הרכיבים - אחרי שכולם זזו.
  4. ציור הפריים על המסך.

ויש עוד שעון: FixedUpdate - קצב קבוע, בשביל הפיזיקה. גם הטריגרים קשורים אליו.
פרטים - בשבוע הבא.
